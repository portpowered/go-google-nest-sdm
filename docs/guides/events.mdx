# Pub/Sub events

The primary integration is stateless: your application receives a Pub/Sub message or HTTP push request, authenticates its delivery, decodes the event and runs its handler. The SDK does not own your web server, callback routing, push identity verification or acknowledgement response.

For an existing Pub/Sub client, pass its decoded message data directly:

```go
result, err := sdm.HandleEvent(ctx, sdm.HandleEventRequest{Data: message.Data},
    sdm.EventHandler(func(ctx context.Context, event sdm.EventEnvelope) error {
        return handleEvent(ctx, event)
    }),
)
```

`HandleEvent` decodes and invokes your callback synchronously; it starts no goroutines and stores no state. Acknowledge through your Pub/Sub client only after it succeeds. For wrapped HTTP push JSON, decode the wrapper first:

```go
result, err := client.DecodePushEvent(ctx, sdm.DecodePushEventRequest{
    Body: requestBody, // Wrapped Pub/Sub push JSON, including base64 message.data.
})
if err != nil {
    // Report failure through your application's HTTP response or consumer policy.
    return err
}
err = handleEvent(ctx, result.Event)
```

`handleEvent` is your application callback. Verify the push identity and expected audience before decoding; return a successful HTTP acknowledgement only after processing succeeds. Handler or decode failures must not be acknowledged as success. Set `Unwrapped: true` when `Body` is raw SDM event JSON, including an unwrapped push body or already-decoded Pub/Sub message data. The decoder performs no network calls and keeps no account state.

Configure Device Access event publishing and a Google Cloud subscription using Google's [current event setup](https://developers.google.com/nest/device-access/api/events). Follow its self-hosted topic guidance rather than copying an old shared-topic identifier. After creating the subscription, make an SDM `ListDevices` call once to initiate publishing. Your application owns subscription/IAM provisioning and the push endpoint's authentication.

Treat deliveries as potentially duplicated and make your handler idempotent. Delivery order can differ from event order; use event timestamps when reconciling cached state. Envelope event IDs, camera event IDs, event-session IDs, event-thread IDs and Pub/Sub message IDs have different purposes. Keep the envelope metadata, namespaced event keys and unknown values when forwarding events.

To maintain a caller-owned cache, use `sdm.Reconcile(sdm.ReconcileRequest{State: state, Event: result.Event})` and persist its returned `State`. It copies the input, binds the first event's user, and reports `Applied`, `Duplicate`, `Stale`, `Unrelated` or `Unsupported` through typed disposition constants. It retains 256 recent event IDs for duplicate detection; older duplicates need your own persistence policy. Strictly older timestamps are ignored; equal timestamps follow delivery order. Relation updates can reassign the parent or mark a deleted device. These are local reconciliation policies, not delivery guarantees.

Resource trait updates are partial patches. Missing fields leave cached values intact; an empty capability trait is still meaningful. Known motion, person, sound, chime and clip-preview events have separate shapes. Clip preview uses `eventSessionId` and `previewUrl`; it does not require the camera event ID used by image generation. Relation updates are separate from resource updates and may contain an empty subject. Unknown event names/fields remain preserved; malformed known payloads remain errors.

An optional pull adapter consumes an existing subscription through REST:

```go
session, err := client.OpenEventSession(ctx, sdm.OpenEventSessionRequest{
    Auth: sdm.AuthContext{AccessToken: pubSubToken},
    Subscription: "projects/CLOUD_PROJECT/subscriptions/SUBSCRIPTION",
})
// Check err before using session.
defer session.Close()
delivery, err := session.Next(ctx)
// Check err, then successfully process delivery.Event() before acknowledging.
err = delivery.Acknowledge(ctx)
```

Pull requires a separate Cloud credential with subscription-consumption permission. `ModifyAckDeadline(ctx, sdm.AckDeadlineRequest{Seconds: 60})` extends a delivery deadline; zero releases it for redelivery. Closing the session cancels its work, is safe to repeat and leaves unprocessed deliveries unacknowledged. Context cancellation stops waiting. Renew credentials explicitly and reopen with the new token when needed.

See the [generated event reference](/docs/asyncapi/events/receiveEvents) and Pub/Sub [pull](/docs/openapi/pubsub/Pull), [acknowledge](/docs/openapi/pubsub/Acknowledge) and [modify deadline](/docs/openapi/pubsub/ModifyAckDeadline) references. The optional adapter uses pull, acknowledge and modify-ack-deadline; it does not open streaming gRPC connections. The initial documented contracts are tested with synthetic fixtures, without live endpoint evidence.
